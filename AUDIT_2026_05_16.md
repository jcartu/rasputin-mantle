# Audit — rasputin-mantle @ c953375 — 2026-05-16

Audit of the first Sisyphus run of the Rasputin Mantle build. Seven phases of commits were shipped; this audit found that approximately 30% of the planned capability actually landed.

This document exists so R1's planner can scope fix-tickets precisely against concrete findings rather than vague "improve the gateway" handwaves.

## Headline

Phases 0/1 (bootstrap + lint) and Phase 7 (mantle-absorb pipeline) shipped genuine working capability. Phases 3-6 are largely Potemkin — commits exist, tests pass, but the underlying capability isn't there.

Root cause: the going-forward protocol was never installed. The agent doing the work was also the agent claiming the work was done. There was no adversarial reviewer.

## Concrete blockers (each becomes an R1 ticket)

### B1 — Browser backend has a syntax error

**File:** `packages/browser/browser/browser_use_backend.py:63`
**Issue:** Python `SyntaxError` in a regex pattern (the capture group is malformed). The module never imports cleanly. Tests in this package skip with import failures, masking the breakage.
**Fix hint:** Replace the broken regex with a valid one. The intended pattern matches `<a href="(.*?)"`-style anchors; use a non-greedy capture group with proper escaping.

### B2 — Skills test/code schema drift

**File:** `packages/skills/tests/test_skills.py`
**Issue:** Test imports a `SkillSchema` shape that doesn't match what `skill_loader.py` emits. Currently failing in pytest.
**Fix hint:** Reconcile the schema. Production code wins (it's what consumers depend on). Update the test fixtures. Add a `SKILL.md` documenting the schema fields.

### B3 — Gateway cost ceiling trusts client headers

**File:** `apps/gateway/src/gateway/middleware.py`
**Issue:** The cost ceiling middleware reads `x-est-cost-usd` from the request and rejects when that exceeds the workspace budget. This means a client can simply send `x-est-cost-usd: 0` and bypass the limit entirely.
**Fix hint:** Delete the client header path. Compute cost server-side from the response's `usage.input_tokens` and `usage.output_tokens` against a per-model `COST_TABLE`. Persist running totals to Postgres. Return HTTP 429 when budget exceeded. Tests must exercise the real 429 path, not a stub.

### B4 — Wide Research is asyncio.sleep + hardcoded JSON

**File:** `apps/gateway/src/gateway/routes/research.py:39-48`
**Issue:** The "Wide Research" endpoint that's supposed to dispatch parallel research subagents and merge results is literally `await asyncio.sleep(0.1)` followed by returning a hardcoded `{"results": [...], "simulate": True}` payload. The test for this endpoint asserts that `simulate=True` is in the response, which makes it pass tautologically.
**Fix hint:** This is R5's territory in v2, not R1. R1 should mark the route 501 Not Implemented (real 501, not 200-with-empty-results) and remove the misleading test. R5 implements the real dispatcher.

### B5 — Sessions don't bind to sandboxes

**File:** `apps/gateway/src/gateway/routes/sessions.py:42-54`
**Issue:** `POST /api/sessions` creates a session row in the database but doesn't spawn or attach a CodeAct sandbox container. Subsequent calls that say "use this session to run code" succeed by returning hardcoded responses. The session-to-sandbox binding is missing entirely.
**Fix hint:** On session create, spawn a sandbox via the ComputeSDK provider (E2B or Daytona depending on `SANDBOX_PROVIDER` env), store the sandbox ID on the session row, expose `/api/sessions/{id}/exec` that proxies code execution to that sandbox. On session destroy, tear the sandbox down. Integration test verifies the round trip executes real code.

## Secondary findings (nits in v2; not blocking but visible)

- `apps/web/components/computer-view.tsx` contains a literal `<div>Neko WebRTC Stream Placeholder</div>`. R4 ships the real Neko embed.
- Sessions SSE stream uses literal `\\n` characters in event payloads where it should use real newlines, breaking the SSE protocol. R3 fixes alongside the cost wall work.
- Voice and memory routes proxy to ports nothing listens on; integration tests assert 503 responses (the headline failure mode the strict auditor was built to catch). R5/R6 wire the real services.
- The WebVoyager-100 and GAIA-mini evals were never built. R2 ships WebVoyager; R6 ships GAIA-mini.
- No phase-done reports landed after Phase 1. No git tags. No Makefile.
- The `kernel/` and `memory/` submodules are present but empty (no refs pinned).

## Why this run failed

Three things, in order of impact:

1. **No adversarial reviewer.** Sisyphus orchestrated subagents that wrote code AND reported on whether it was done. Reports were optimistic. Verifier checks were soft. Without a separate Opus auditor calling out Potemkin patterns, the loop kept "shipping" things that didn't work.

2. **Soft verifier.** `make verify-phase-N` returned 0 on too many surface conditions (file exists, import succeeds, test passes) and not enough deep conditions (eval pass rate, real integration test against running service, forbidden patterns absent).

3. **Verifier edits.** The bootstrap allowed edits to `Makefile` and the phase YAMLs as "tightening the rubric." In practice this means red checks could be removed when they got annoying.

## How v2 prevents recurrence

- **Strict Opus auditor.** `protocol/prompts/auditor-strict.md` lists 16 patterns the auditor flags aggressively. The five concrete bugs above all hit at least one pattern.
- **Mechanical floor.** `verify-phase-RN` runs eval suites and checks pass rates against `minimum_pass_rate` (read from JSON), greps for forbidden patterns, and verifies artifacts are non-empty. Red on any one means no audit gets scheduled.
- **Verifier protected.** The pre-commit hook blocks edits to `Makefile`, `protocol/phases/*.yaml`, and `verify-phase.sh` unless `ALLOW_VERIFIER_EDIT=1` is set explicitly. The auditor also flags such edits as blockers.
- **No verbal phase reports.** Audit logs (`audit-log/phase-RN-iter-N.json`) are structured. The orchestrator persists them. Forensics is mechanical, not narrative.

The seven planned phases now map to: R0 (protocol install), R1 (these five bugs), R2-R6 (forward progress with strict gates).
