ANTI-CHEATING POLICY (READ THIS, IT MATTERS)
═══════════════════════════════════════════════════════════════════════════════

The point of v1.1 is REAL improvement. The auditor will reject any of the following:

  - Memoizing answers from previous runs and replaying them
  - Hardcoding patterns that match WebVoyager-specific expected_answer formats
  - Skipping tasks because they're "hard" (mark them attempted-failed, don't remove)
  - Lowering the success criterion or grading threshold to ease passing
  - Pre-fetching answers from any external answer key
  - Using a different/easier task set and calling it WebVoyager-100
  - Using a more lenient judge model (e.g., switching from Sonnet to Haiku for grading)
  - Hand-tuning the agent's responses to known WebVoyager tasks
  - Running tasks multiple times and reporting only the best run
  - Inflating pass rate by mass-classifying borderline answers as PASS

ALLOWED (and encouraged):
  - Better browser primitives (waits, retries, multi-strategy selectors)
  - Vision-language model fallback when DOM is opaque
  - Self-correction loops where the agent re-evaluates its strategy
  - Better prompting for the planner (general — not task-specific)
  - Multiple parallel attempts where the final answer is voted (not best-of-N)
  - Expanding the test set with more tasks (not contracting)
  - Using stronger general-purpose models as they become available

The auditor checks for these patterns at S6 audit time. If any are found, S6 fails and we re-do whatever phase introduced them.
